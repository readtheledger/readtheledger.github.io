# Pageview emission and browser exclusion

Production collection is **off**: `GC_SITE` is empty. The optional adapter is ready, but no analytics request is sent. A future enablement must use a verified owner-controlled account and update the public disclosure to match. Reachability of an endpoint alone is not proof of control.

## Count model when configured

| Visible destination | Count path |
| --- | --- |
| Front page | `/` |
| Editorial section | Its existing canonical section path |
| Original article | Its existing `/story/<id>/` path |
| About | `/about/` |
| Newsstand list | `/newsstand/` (aggregate analytics label, not a new public route) |
| Saved list | `/saved/` (aggregate label; no saved contents) |
| Any Newsstand reader | `/newsstand/reader/` (aggregate label; no item ID, title or publisher URL) |

The browser emits once when the visible destination changes. Direct entry counts the final destination, not the hidden home page used for history. Opening another story, Back/Forward, closing the reader, switching sections, a document reload, or restoration from the back-forward cache can count a new view. Selecting the current section or redrawing it does not.

The last destination is held only in memory. It is not a timed deduplication window or visitor identifier. Returning to a previously visited page counts again. Newsstand item identities distinguish reader transitions locally but are not sent.

Search input, search-result redraws, overlays, settings, saving, audio controls and feed refreshes are not pageviews. URL/history behavior is preserved: section selection replaces the URL in place and does not create a new history entry. No click-through or returning-person metric is implemented.

## Exclude this browser

Open Menu → About The Ledger → Pageview counting and your choice. Check **Exclude my visits**. The preference persists in local storage and applies across tabs on this origin; uncheck to reverse it. Changing the choice does not emit or replay a view. With collection off, this merely saves a preference for any future enablement.

Set it separately for each browser/profile. Clearing site storage removes it. The adapter also honors the existing GoatCounter `skipgc=t` preference. If the preference cannot be read or written, counting pauses in the current document and the control explains that persistence could not be established. No choice can retract a request sent before it was selected.

## Request and environment boundaries

The configured pixel uses only `p` (an allowlisted public path/aggregate label) and `rnd` (a cache-busting timestamp). It does not send titles, query strings, fragments, credentials, search text, campaign values or referring addresses. The image has `referrerPolicy="no-referrer"`; unsupported browsers do not send it. No new source-attribution field is implemented.

Only the exact canonical HTTPS origin can emit. Local files, local/preview hosts, frames, prerenders before activation, WebDriver and recognized automation/bot user agents are excluded. This is not exhaustive bot detection. The app adds no persistent visitor ID, fingerprint or tracking cookie. Ordinary connection metadata would still be visible to a configured collector.

The [documented pixel protocol](https://www.goatcounter.com/help/pixel) supports these parameters. GoatCounter's [JavaScript reference](https://www.goatcounter.com/help/js) and [exclusion guidance](https://www.goatcounter.com/help/skip-dev) informed the adapter; no external script is loaded. Sources checked 2026-09-12.

**Emission is not receipt or a dashboard denominator.** GoatCounter's [sessions documentation](https://www.goatcounter.com/help/sessions) explains that default dashboard visits can deduplicate repeat pageviews. A future owner-accessible report must establish actual receipt, exclusions, settings and units before a traffic baseline or experiment begins. No account setting is changed here.

## Verification

`python qa_analytics.py` builds a fixture and intercepts **every** browser request. A collector code is substituted only in locally fulfilled test HTML; all pixel requests are recorded and aborted. The unmodified production configuration is tested separately for zero requests. No live collector/site/advertising traffic is generated by this suite.

Checks cover direct and in-app entries, reader-to-reader navigation, Back/Forward, immediate revisits, reloads, bfcache and prerender activation, sections/app views, search/control non-events, payload allowlisting, no forwarded private referrer, opt-out/re-enable/reload/cross-tab behavior, storage failures, local/preview/automation exclusions, and accessible mobile control sizing. bfcache/prerender lifecycle events are simulated; this is headless Chromium, not a physical-device certification.

`build.mjs` copies and hashes `analytics.js`; the service worker precaches it and the deployment artifact check requires it. Existing core, package-1 navigation and SEO suites remain relevant. Test artifacts stay local under `.qa/`.
